# 设计说明

[English](../design.md) · [用户指南](README.md) · [首页](../../README.zh-CN.md)

不同实验室开放的控制范围各不相同：有的设施接受完整实验工作流，有的提供单台仪器的功能。SCP-Lab 为调用方提供共同的方式，发现这些能力、请求操作并解释返回的证据，在复用接入工作的同时保留每项操作的实验含义。

## 五个访问级别

访问级别描述一项能力向调用方开放哪些选择。每个级别都可以包含可调参数。级别取决于发布的接口，同一台仪器可以提供不同级别的能力。

| 级别 | 访问形式 | 调用方可以控制什么 | 示例 |
| --- | --- | --- | --- |
| L1 | 既定工作流 | 固定工作流的输入与实验条件 | 选择合成配方和反应温度 |
| L2 | 可配置工作流 | 工作流中开放步骤的选择与排列 | 安排加样、反应和测量阶段 |
| L3 | 单设备功能 | 内部顺序固定的功能所接受的输入与参数 | 请求一次移液或读板 |
| L4 | 设备内部操作 | 设备功能内部操作的选择、顺序与重复 | 编排吸液与排液操作 |
| L5 | 执行器动作 | 开放的运动或驱动指令 | 指定姿态、导轨位置或夹爪动作 |

例如，酶标仪可以在 L3 开放固定的“振荡后读板”功能，在 L4 开放由调用方配置的“振荡、读板、再振荡、再读板”过程。复用一项能力时，还需要匹配输入 schema、样品与容器、操作条件和完成标准。

内置设备功能主要属于 L3。多设备示例由客户端依次发起调用；发布为 L2 的能力则会作为独立服务接收并执行可配置工作流。判断级别时，应看调用方获得的控制范围，而不是实现内部生成了哪些指令。

## 能力、状态与执行记录

这三类对象分别回答不同的问题：

| 对象 | 回答的问题 | 主要内容 |
| --- | --- | --- |
| `DeviceDescriptor` 中的能力 | 我能请求什么？ | 输入与结果 schema、单位、默认值、访问级别和完成标准 |
| `DeviceState` | 实例目前是什么状态？ | 可用性、占用情况，以及带来源和时间的可选观测 |
| `ExecutionRecord` | 这次请求经历了什么？ | 原始与生效参数、版本、状态、进度、结果和依据 |

以恒温操作为例，能力描述可接受的范围和单位，请求给出目标温度与时长。如果后端提供温度观测，设备状态可以报告实测值。执行记录保存采用的参数，以及支持完成判断的依据。

这样的划分让应用复用发现和生命周期处理逻辑，同时保留设备专属参数与结果。具体字段见[协议参考](device-access.md)。

## 从请求到下一个实验步骤

```text
发现实例 → 读取能力 → 提交明确的操作请求
                              ↓
                       接受任务（run_id）
                              ↓
                        查询状态与进度
                              ↓
                       检查结果和完成依据
                              ↓
                    调用方判断下一步的执行条件
```

任务被接受后，调用方获得任务标识。完成依据解释结果的来源，例如 schema 校验通过、mock 执行轨迹、仿真器运行日志或物理观测。设备是否释放单独记录，因为操作结束后，设备仍可能需要处理才能继续使用。

编排有依赖关系的操作时，调用方应用在启动下一步前检查样品、容器、位置和共享资源。例如，读板需要先完成制样、收到正确的板，并确认酶标仪可用。任务与样品引用将测量结果关联到产生它的实验。

## MCP 兼容接口

SCP-Lab 将能力描述、设备状态和执行记录定义为独立于接入接口的数据结构。MCP 兼容接口把能力查询、任务提交、状态与结果查询映射为现有客户端可以调用的工具，并保留 SCP-Lab 对参数、状态和完成依据的定义。

本仓库提供本地 stdio 接入。客户端配置见[应用接入指南](clients.md)，工具响应与运行时行为见[协议参考](device-access.md)。
